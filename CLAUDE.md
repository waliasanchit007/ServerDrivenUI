## Architecture Overview

This is a Kotlin Multiplatform (KMP) project for Caliclan Gym featuring a server-driven UI system using Redwood and Zipline. The app targets Android and iOS, with a web admin dashboard.

### Core Architecture: Server-Driven UI with Redwood

The project uses **Redwood** for a declarative server-driven UI system:

1. **Schema Layer** (`schema/`): Defines the UI component schema using `@Schema` and `@Widget` annotations. These are abstract widget interfaces.
2. **Widget Layer** (`shared-widget/`): Generated widget interfaces from the schema.
3. **Protocol Layer** (`shared-protocol-host/`, `shared-protocol-guest/`): Generated serialization protocols for sending UI over the wire.
4. **Host Layer** (`composeApp/`): Compose Multiplatform widgets implementing the schema (Cmp* classes in Protocol.kt).
5. **Guest/Presenter Layer** (`presenter/`): JavaScript code running in Zipline that constructs the UI using the protocol widgets.

The flow: JavaScript (Guest) → Protocol (Wire format) → Host (Compose Widgets) → Native UI.

### Module Structure

- **schema/**: Redwood schema definitions (`Schema.kt`). This is the source of truth for all UI components.
- **shared-widget/**: Generated widget interfaces (read-only, generated by Redwood).
- **shared-protocol-host/**: Generated host protocol for serialization (read-only).
- **shared-protocol-guest/**: Generated guest protocol for serialization (read-only).
- **shared/**: Shared services, app spec, and DTOs used by both host and guest.
- **composeApp/**: Main shared Compose Multiplatform code including:
  - `Protocol.kt`: Widget factory implementations (Cmp* classes)
  - `App.kt`: Main app composable with Treehouse integration
  - `SharedAppSpec.kt`: Platform-agnostic Treehouse app spec
- **presenter/**: JavaScript-based UI that runs in Zipline. Contains screen implementations (`HomePresenter`, `LoginScreen`, etc.).
- **core-data/**: Data layer with Supabase integration (`SupabaseGymRepository.kt`).
- **androidApp/**: Android application entry point (`MainActivity.kt`).
- **admin-web/**: Web admin dashboard for managing gym data.
- **dev-server/**: Ktor development server for testing Zipline loading.

## Development Commands

### Build Commands

```bash
# Build Android app
./gradlew :androidApp:assemble

# Build iOS framework
./gradlew :composeApp:linkReleaseFrameworkIosArm64
./gradlew :composeApp:linkReleaseFrameworkIosSimulatorArm64

# Build presenter (JavaScript)
./gradlew :presenter:jsBrowserProductionExecutable

# Build all
./gradlew build
```

### Development Server

```bash
# Start development server for Zipline hot-reload
./gradlew :dev-server:run
```

The dev-server serves the compiled JavaScript from the presenter module, allowing hot-reload development of the server-driven UI.

### Testing

```bash
# Run all tests
./gradlew test

# Run tests for a specific module
./gradlew :core-data:test
```

## Key Concepts

### Adding New Widgets

1. **Define in schema**: Add a new `@Widget` class to `schema/src/main/kotlin/com/example/serverdrivenui/schema/Schema.kt`
2. **Implement in host**: Add implementation class in `composeApp/src/commonMain/kotlin/com/example/serverdrivenui/shared/Protocol.kt`
3. **Register in factory**: Add to `CmpWidgetFactory` in Protocol.kt
4. **Use in presenter**: Import and use in `presenter/src/jsMain/kotlin/com/example/serverdrivenui/presenter/screens/*.kt`

The Redwood plugin will automatically regenerate widget interfaces and protocols.

### Navigation

The app uses a **Guest-Driven Navigation** architecture. The JavaScript presenter controls navigation via the `Navigator` class. The host (Android/iOS) doesn't manage navigation state.

### Services and Data

- **GymService**: Abstract interface for gym operations
- **RealGymService**: Implementation wrapping `SupabaseGymRepository`
- **SupabaseGymRepository**: Ktor-based Supabase REST API client

Services are bound to Zipline via `SharedAppSpec.bindServices()` and can be accessed in JavaScript via `zipline.take<GymService>("gym")`.

### Date/Time Handling

Platform-specific date operations are abstracted through `PlatformDateProvider` to ensure consistency across Android, iOS, and JavaScript.

## Important Files

- `schema/src/main/kotlin/com/example/serverdrivenui/schema/Schema.kt`: UI schema - modify here to add new widgets
- `composeApp/src/commonMain/kotlin/com/example/serverdrivenui/shared/Protocol.kt`: Widget implementations
- `composeApp/src/commonMain/kotlin/com/example/serverdrivenui/shared/SharedAppSpec.kt`: Service bindings and app spec
- `presenter/src/jsMain/kotlin/com/example/serverdrivenui/presenter/Main.kt`: Zipline entry point and service bindings
- `core-data/src/commonMain/kotlin/com/example/serverdrivenui/core/data/SupabaseGymRepository.kt`: Data layer implementation

## Configuration

- Supabase configuration is in `shared/src/commonMain/kotlin/com/example/serverdrivenui/shared/SupabaseConfig.kt`
- Dev configuration in `composeApp/src/commonMain/kotlin/com/example/serverdrivenui/shared/DevConfig.kt`

## Platform-Specific Notes

### Android
- Uses CameraX and ML Kit for QR code scanning (in `composeApp/src/commonMain/kotlin/com/example/serverdrivenui/native/screens/AttendanceScannerScreen.kt`)
- Entry point: `androidApp/src/main/kotlin/com/example/serverdrivenui/MainActivity.kt`

### iOS
- Framework is built as a static framework
- Entry point is in the `iosApp` directory (Xcode project)

### Web (Admin)
- Built with Compose Multiplatform for Web
- Runs in browser at `admin-web/src/commonMain/kotlin/Main.kt`

## Generated Code

The following directories contain generated code that should **not** be manually modified:
- `shared-widget/build/generated/redwood/`
- `shared-protocol-host/build/generated/redwood/`
- `shared-protocol-guest/build/generated/redwood/`

To regenerate: Run `./gradlew :shared-widget:generateRedwoodInterface` or simply build the project.
